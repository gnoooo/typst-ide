2. КАК УСТРОЕН ПЕРЕВОД В ПРОЕКТЕ
================================================================================
Механизм находится в frontend/src/i18n/.

  frontend/src/i18n/index.js
      Движок i18n:
        import fr from './fr.json'
        import en from './en.json'
        import ru from './ru.json'
        const locales = { fr, en, ru }

      Экспортируемые функции:
        t(key, params)      — возвращает строку по ключу; если ключа нет,
                              возвращает сам ключ; подставляет {name}-параметры.
        getLang()           — текущий язык ('fr' | 'en' | 'ru').
        getLocaleTag()      — тег локали для дат: fr-FR / en-US / ru-RU.
        setLang(lang)       — переключает язык, пишет его в localStorage('lang'),
                              ставит document.documentElement.lang и вызывает
                              applyI18n().
        applyI18n(root)     — применяет переводы к DOM.
        initI18n()          — при старте: сохранённый язык из localStorage,
                              иначе system_lang через Tauri, иначе
                              navigator.language (первые 2 символа), иначе 'en'.

  frontend/src/i18n/en.json
  frontend/src/i18n/fr.json
  frontend/src/i18n/ru.json
      Плоские JSON-объекты «ключ — строка». Ключи с точками, например:
        "menu.file": "Файл"
        "filesync.save_error": "Ошибка сохранения: {error}"
      Во всех трёх файлах набор ключей обязан совпадать.
      В ru.json сейчас 413 ключей (как и в en/fr после добавления
      lang.russian).

  Разметка HTML:
      data-i18n="ключ"              — заменяет textContent
      data-i18n-placeholder="ключ"  — заменяет placeholder
      data-i18n-title="ключ"        — заменяет title (подсказку)
      data-lang="ru"                — кнопка переключения языка

  Переключение языка:
      frontend/src/js/main.js      — обработчики кнопок [data-lang]
      frontend/src/js/tutorial.js  — отдельное окно обучения, свои кнопки

7. ИНТЕГРАЦИЯ В УЖЕ УСТАНОВЛЕННУЮ ПРОГРАММУ
================================================================================
Важно: Tauri встраивает frontend/dist внутрь исполняемого файла на этапе
компиляции (frontendDist = ../../frontend/dist). Отдельного внешнего файла
перевода в установленной программе НЕТ. Просто положить ru.json рядом с exe
недостаточно — нужно заменить сам exe на пересобранный.

Текущая установка на этой машине:
  C:\Users\greg\AppData\Local\Typst IDE\typst-ide.exe
  Версия: 1.8.0
  Ярлык: %APPDATA%\Microsoft\Windows\Start Menu\Programs\Typst IDE.lnk

Быстрый путь (замена exe):

  # 1. Закрыть приложение
  Get-Process typst-ide -ErrorAction SilentlyContinue | Stop-Process

  # 2. Резервная копия
  Copy-Item "$env:LOCALAPPDATA\Typst IDE\typst-ide.exe" `
            "$env:LOCALAPPDATA\Typst IDE\typst-ide.exe.bak-1.8.0"

  # 3. Заменить на новую сборку
  Copy-Item "Z:\github\typst-ide_rus\target\release\typst-ide.exe" `
            "$env:LOCALAPPDATA\Typst IDE\typst-ide.exe" -Force

Альтернатива: запустить собранный NSIS-инсталлятор
  Typst IDE_1.8.1_x64-setup.exe
Он обновится поверх, пользовательские данные сохранятся (тот же identifier
io.github.gnoooo.typst-ide).

После запуска выбрать язык:
  Справка > Язык > Русский
  (Help > Language > Русский)

Если язык ещё не выбирался вручную и системная локаль русская, initI18n()
через команду system_lang определит 'ru' автоматически. Если в localStorage
уже сохранён 'fr' или 'en', он имеет приоритет — язык надо переключить в меню.

9. ВОЗМОЖНЫЕ ПРОБЛЕМЫ И РЕШЕНИЯ
================================================================================
Проблема: после переключения на русский часть строк осталась французской.
  Причина: у элемента нет data-i18n (или data-i18n-placeholder/title).
  Решение: добавить атрибут в HTML и ключ во все три JSON.

Проблема: ключ отображается как есть, например "menu.file".
  Причина: ключа нет в текущем JSON или файл не импортирован в locales.
  Решение: проверить ключ во всех трёх JSON и запись в index.js.

Проблема: сломалась подстановка {error}/{name}.
  Причина: плейсхолдер переведён или удалён.
  Решение: оставить {error}, {name} и т. п. без изменений.

Проблема: русский не включился автоматически.
  Причина: в localStorage уже сохранён lang = 'fr'/'en'; он приоритетнее
  системной локали.
  Решение: выбрать язык в меню либо удалить сохранённое значение.

Проблема: Vite не видит русские markdown-файлы.
  Причина: папка/файлы отсутствуют на момент сборки или нарушена нумерация.
  Решение: проверить frontend/src/tutorial/ru/*.md и glob "../tutorial/ru/*.md".

Проблема: кириллица выглядит «кракозябрами» в консоли PowerShell.
  Причина: кодировка консоли, а не файла. Файлы записаны в UTF-8 без BOM.
  Проверка: прочитать через
    [System.IO.File]::ReadAllText(path, [System.Text.Encoding]::UTF8)
  или проверить коды символов:
    "Файл".ToCharArray() | ForEach-Object { [int]$_ }  # 1060,1072,1081,1083

Проблема: собранный exe не запускается / SmartScreen.
  Причина: сборка без подписи.
  Решение: «Подробнее > Выполнить в любом случае» либо использовать NSIS-
  инсталлятор. Для работы нужен WebView2 Runtime.

Проблема: `cargo tauri build` не найден.
  Причина: Tauri CLI установлен через npm, а не через cargo.
  Решение: использовать `npx @tauri-apps/cli@2.12.0 build ...` или
  `cargo install tauri-cli --version 2.12.0`.
